# 2026.241.0945 — feat(unit): the unit verb — a systemd unit file with no cross-init analogue

## Summary

The `unit` verb, re-landed for review after PR #1 removed the unreviewed bootstrap commit. The last
item of batch **B4**.

charly can already declare a **service**, and `service:` is deliberately init-agnostic: it renders to
supervisord, systemd or OpenRC alike. But a `.socket`, `.target` or `.slice` has **no analogue** on
the other two inits, so it cannot become a `service:` entry without handing them something they have
no concept of.

Candies therefore hand-roll those as `write:` + `command: systemctl daemon-reload && systemctl
enable` — the manual `systemctl` against a charly-managed resource R4 forbids. Three things are
wrong with that shape, and all three are why this verb exists:

1. the write is **unowned**;
2. the reload is a **separate step**, so a failure between them leaves a unit on disk the manager has
   never read;
3. nothing can **assert** the result.

```yaml
- run: unit=cstream-broker.socket
  unit:
    unit: cstream-broker.socket
    enable: true
    content: |
      [Unit]
      Description=cstream broker socket
      [Socket]
      ListenStream=/run/cstream/broker.sock
      [Install]
      WantedBy=sockets.target

- check: the broker socket is installed and enabled
  unit: {unit: cstream-broker.socket, enable: true}
  context: [runtime]
```

## Naming and scope

**`unit`, not `systemd_unit`.** A reserved word naming a concrete init re-creates exactly what the
data-driven `init:` kind eliminated. The init is a **field** (`scope: system|user`), never part of
the verb's name.

**Not `.mount`.** `plugin-mount` already owns that with `#MountInput{mount, mount_source, filesystem,
opt}`. Reuse the seam that exists.

**`active` is probe-only.** Starting a unit is a deployment action, and `service:` already owns "this
should be running". The act writes, reloads and enables — it does not start.

## Design choices the tests pin

Each is a way this could be **quietly wrong** rather than loudly broken:

- **Existence is probed with `systemctl cat`, not a file test.** A unit written to a directory the
  manager does not read exists on disk and is still not a unit — the failure `[ -e ]` cannot see. The
  message says so.
- **`enable`/`active` are tri-state.** Unset probes *nothing*, so a socket started by another unit's
  `Requires=` is not forced to own an `[Install]` section it does not have.
- **A drop-in has no identity.** `systemctl is-enabled 50-cstream.conf` is meaningless, so the probe
  targets the unit the fragment extends **and** checks the fragment is among the resolved fragments —
  a file that exists but is not applied is the real bug.
- **The heredoc delimiter is quoted.** Unit files are full of `$` and `%`; `%i` and `$MAINPID` belong
  to systemd, not the shell.
- **The act declines a step with no content** rather than rendering an empty script, which would make
  charly believe it acted.
- **write → daemon-reload → enable order is asserted**, not assumed.

## Not covered

  while the hand-rolls are deleted. That is B4's remaining sub-unit.
- **No live systemd venue.** A rootless pod has no systemd-logind or system manager, so `daemon-reload`
  and `enable` are proven to *render*, not to *take effect*. The cstream VM bed is where that closes —
  and it is the first consumer, needing exactly a `.socket`, a `.target` and a `.slice` drop-in.
